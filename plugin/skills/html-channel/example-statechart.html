Saving an answer

Every control on an html-channel page goes through the same few states between the reader's click and the server's copy. The runtime keeps no explicit state machine: the states below are the values of each control's data-state and the page's online flag, in runtime/decide/core.cljs. The repo's root, /path/to/html-channel, is a placeholder: set it to your checkout in the code-links bar at the top. The GitHub links work as they are.

One answer

Start with a single control, and leave the connection folded away. A CHANGE queues the answer and sends the queue at once: the answer becomes saved, or rejected if the server refuses it. If the server can't be reached, it stays pending. On a reload, an answer from an earlier revision of the page comes back as carried. And the connection

Now unfold connection. The runtime polls the server every three seconds, and each poll sends whatever is still queued. Untick serverUp in the context panel, then change an answer:

Notice that the answer waits in pending with the queue at 1, the connection drops to offline at the next poll, and ticking serverUp again doesn't save it at once: the next poll does, within three seconds. The refined state is connection; the answer's states keep their names and places.
