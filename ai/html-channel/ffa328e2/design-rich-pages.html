Rich context pages: design

Six independent choices, each with 3–4 candidates. Pick one per axis.
The diagram shows how axes 1–3 fit together. Folds hold the provenance.

The same five dimensions apply to every candidate. Reliability: how likely a blind agent gets it right. Reach: Claude Code, Desktop, ECA, CLI. Deps: what the install gains. Fit: how well it meets frame constraints (ai/frame.md). Cost: build plus upkeep. ● good ● mixed ● poor

1. How a page declares and uses libraries

Settled: libraries are declared in <head>, come from a pinned CDN, may be any library, and the kit suggests some. Open: whether the agent writes glue code for each library.

CandidateReliabilityReachDepsFitCost
1a Raw tags. CONVENTION lists pinned URLs; the page adds a <script src> plus its own init code. ● init glue each time; errors silent● all● none● declared, any library● docs only
1b Kit adapters + escape hatch.rec
For suggested libraries, the page writes <pre data-viz="mermaid">…</pre> and lists them in <meta name="hc-libs">; the kit loads the pinned CDN build, renders, and routes parse errors to axis 2. Any other library uses 1a.		 ● no glue for suggested libraries; errors caught● all● none at install● declared, any library, answers still via runtime● one adapter per library plus version bumps
1c Server-injected import map. The server adds an <script type="importmap"> aliasing mermaid etc.; the page writes module code with bare imports. ● still glue; no version typos● all● none● server rewrites agent HTML, which is new● rewriting in the server
Provenance
  • "Declared, pinned CDN, any library, kit suggests": user input (frame rev 1–2).
  • 1a: established pattern; this session's Artifact tool spec does the same (pinned-version CDN allowlist). Research finding.
  • 1b: LLM inference. Its error path relies on Mermaid's parse(…, {suppressErrors})/parseError (research finding) and on the render-constraint gap: 51% → 60% → 96% with verifier repair (research finding).
  • 1c: established web pattern (import maps); the server-injection variant is LLM inference.

2. How the agent learns what rendered

Settled: render feedback is in scope. Open: whether it arrives before the reader sees the page, and at what install cost.

CandidateReliabilityReachDepsFitCost
2a In-page capture. The runtime listens for error (capture phase) and unhandledrejection, posts them to the server, and ask_human returns errors. ● JS and load errors yes; visuals no; only after a human opens the page● all● none● reader sees the broken page first● small
2b 2a + headless check.rec
New check_page tool and html-channel check command: they run system Chrome headless (light and dark), the 2a runtime reports errors during that load, and the result returns {errors, screenshots}. Without Chrome it falls back to 2a.		 ● JS, load and visual problems, before the human● all (tool and CLI)● optional system Chrome● bb-only install kept● medium
2c Playwright check. Same as 2b, driven by Playwright. ● catches everything, verified locally● all● Python or Node plus a browser download● breaks the bb-only install● medium
Provenance and test results
  • 2a: research finding (MDN). Resource load failures skip window.onerror but reach a capture-phase listener.
  • 2b: research test on this machine. Chrome --screenshot took 1.4 s; --force-dark-mode reproduced the rev 1 contrast bug; --virtual-time-budget was needed for the runtime to run. Chrome's stderr missed the failed CDN load. Letting the kit runtime report during the headless load closes that gap: LLM inference, untested.
  • 2b limit, observed while checking this page: the Chrome CLI keeps the window at least ~500 px wide, so --window-size=420 clips even a trivial page. Checking at phone width needs device emulation over the DevTools protocol, which the plain CLI doesn't offer.
  • 2c: research test. Playwright caught pageerror, console errors and requestfailed.
  • "bb-only install" constraint: README (repo).

Cross-axis dependencies

  • 2b's screenshots matter less once 4a makes unstyled pages readable, but they still catch overflow and diagram layout.

  • Every candidate except 1a/6c requires the CONVENTION rewrite ("no JavaScript" → "page JS renders; answers through runtime"), along with the skill and #html.
