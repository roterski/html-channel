html-channel: quick guide

An agent writes a static HTML page. You answer on it in your browser. The agent reads your answers back. This page is itself an html-channel page: a report-only one, with nothing to answer.

1. Use it

Claude Code (MCP)

The agent calls channel_setup, writes the page, then blocks in ask_human until you click Done.

Skill or CLI

The agent runs session new and gives you a URL. You click Done and say "done". The agent then runs decisions.

ai-behaviors #html

Add #html to a prompt and the agent puts its questions on a page instead of in markdown.

Register the MCP server once

claude mcp add --scope user html-channel -- html-channel mcp
# Claude desktop: add "--max-wait", "50" to args (desktop is said to drop calls after ~60 s)

Or drive it by hand

html-channel serve --root .ai &        # serves this project; stands by if the port is taken
html-channel session new --root .ai    # → {session, dir, url_base}
# write <dir>/<page>.html, open <url_base><page>.html, answer, click Done
html-channel decisions <session>/<page> --root .ai
html-channel health                    # is a server up?

2. Writing pages

The full rules are in CONVENTION.md, the only hand-written copy. Here is the short version:

MarkupSaved as
<button data-decision="id" data-choice="a">"a". Buttons that share an id act as one choice.
<textarea|input|select data-decision="id">the field's text, saved on change
<input type="checkbox" data-decision="id">true / false
<button data-decision="status" data-choice="done">The Done button, required on decision pages
  • Every page links /_kit/decide.css, loads /_kit/decide.mjs, and has a #decide-offline banner that is visible by default.
  • No JavaScript of the page's own. Inline <style> is fine.
  • Page names match [a-z0-9-]+. @ is reserved for snapshots.
  • Report-only pages, like this one, have no Done button, and the agent doesn't wait on them.

3. Revisions

  1. The agent rewrites the same file, .ai/<session>/<page>.html.
  2. The server snapshots it as <page>@<n>.html. That's revision n.
  3. Your open tab notices within 3 s and reloads. Clicks queued before the reload are saved first.
  4. Earlier answers carry over, outlined in purple, with a Clear carried answers button.
  5. Done never carries over: each revision needs its own click.

Every answer is appended to .ai/<session>/decisions.jsonl as {page, session, rev, id, value, at}. Nothing is ever rewritten, so the file is a full history you can commit.

4. How the server stays up

No daemon is needed. Every html-channel mcp and serve process is a standby:

  1. It records its project root in ~/.local/state/html-channel/roots.jsonl.
  2. It tries to bind 127.0.0.1:8787, and retries every second if the port is taken.
  3. The owner serves every registered project at /<project>-<hash>/<session>/<page>.html.
  4. When the owner exits, another process takes over in about 0.6 s, as the takeover test measured.

Session ids are the first 8 characters of Claude Code's session id, or a fresh random id. That's why this page lives under b658090c.

6. Develop

npm i                 # squint, only needed to build the runtime
bb build              # runtime/ → resources/html_channel/kit/, copies CONVENTION.md and the skill
bb test               # unit tests, then B/D, takeover, MCP and revisions in Chromium
bb serve --root examples   # demo at http://127.0.0.1:8787/

Edit CONVENTION.md at the repo root only; bb build regenerates its copies. CI fails if build outputs are stale.

7. Gotchas

  • Stdout belongs to MCP. Log to stderr only, or clients break.
  • Headless claude -p won't exit while a background server it started is still running. Start the server yourself first.
  • After /clear, the MCP process keeps its original session id while Bash gets a new one. Pass session explicitly when you mix the two.
  • ECA times out tool calls at 120 s and runs them one at a time. Use --max-wait 100 and accept that other chats stall.
  • bbin git installs need deps.edn. bb.edn alone fails with "Manifest file not found".
