CONVENTION says "contains no JavaScript" and forbids <script> blocks; #html lists InlinePageScript as forbidden; the skill repeats it. All three conflict with the new JS constraint and must be reworded together. Q1 decides what the replacement rule is.

Q1. With libraries allowed, what's the invariant that stays?

Why it matters

The runtime currently owns every answer: saving, carry-over across revisions, the Done button. If page JS can write answers itself, carry-over and decisions.jsonl stop being trustworthy. The first option keeps that contract and frees everything visual.

Edge: a diagram the reader clicks to choose (e.g. pick a node) would need page JS to set a data-decision control's value — still through the runtime.

Q2. Readability basics (contrast, dark mode, width): defaults or guidance?

Why defaults over guidance

Rev 1's bug was an instruction-following failure the agent couldn't see. A base theme (tokens, contrast-checked colors, dark mode, readable measure) removes that class of failure instead of asking the agent to avoid it. Guidance alone relies on the same blind agent getting it right each time. (#scope)

Q3. Should the agent see what rendered?

Why ask

Free JS from a CDN adds failure modes: lib fails to load, diagram syntax error, overflow. Today none of these reach the agent; the reader sees a broken page and the agent believes it succeeded.
