Draft frame

Situation
html-channel delivers decision pages: static HTML, no page JS, form controls, revisions, answers back to the agent. #html routes decisions there.
Complication
Pages today are markdown-shaped: flat text, a few buttons. HTML's real advantages — diagrams, charts, folds, side-by-side, tiered depth — go unused, and the no-JS rule blocks every diagram/chart library.
Question
What page vocabulary lets a reader grasp a complex subject and decide fast — and which layer (html-channel, ai-behaviors, prompt) owns each part of it?
Constraints
Localhost, single user. Agent authors pages blind (never sees the render). Pages stay agent-writable in one pass. Answers stay plain decisions.jsonl.
Non-goals
Draft below in Q6 — pick what's out.
Tensions found in the current design

No-JS vs libraries. CONVENTION forbids page JS; #html lists InlinePageScript as forbidden. Mermaid, Vega-Lite, etc. all need JS. Something has to give, or move into the kit (Q2).

Reader-driven depth vs blocking wait. ask_human wakes only on Done. A "go deeper here" click can't reach the agent mid-page without either a Done or a new wake signal (Q4).

Blind authoring. The agent can't see whether a diagram rendered or overflowed. Declarative, validated vocab is safer than free-form SVG; a render-error report back to the agent would close the loop.

On "inference"

"From inference" could mean two different things — which did you mean?

  • Kit infers from markup which libs the page needs (= on demand above).
  • Agent infers which representation fits the content (graph → diagram, series → chart, hierarchy → folds). That's a prompting/behavior concern, not a loading one.

Q4. Who controls depth?

Why this matters

Author-only depth means the agent must guess every branch the reader will open — costly, and the bottom tiers mostly go unread.

Reader-driven depth matches #zoom ("the user turns the lens") and uses revisions as the zoom step. It needs a wake signal other than Done (see tensions).

Q5. Is this the right ownership split to investigate?

LayerOwns (hypothesis)
html-channelMechanism. Component vocabulary (tiers/folds, diagram, chart, compare, callout), hydration + lib loading, theming, render-error feedback, CONVENTION as the single spec.
ai-behaviorsShape of thought, channel-agnostic. #zoom/#scq/#delta already define tiers and sections. #html maps those structures onto the vocabulary (e.g. zoom level → fold depth) — nothing more.
PromptingPer-subject choices: which representation fits this content, what to put above the fold.
Open edge: where does "pick the right representation" live?

It's the hardest part and fits none cleanly. Options: a reference section in CONVENTION ("graph-shaped → diagram"), a new behavior (e.g. #visual), or left to the model. Keeping it out of html-channel keeps the tool dumb; keeping it out of ai-behaviors keeps behaviors channel-agnostic.
